# Today Todo v2 제품 명세와 점수 정책

이 문서는 장소·예상시간·완료 여부·수행점수·달력·로컬 기록과 날짜별 회고의 구현 기준이다. 화면·상태·저장이 같은 정책을 적용하도록 계산과 경계 조건을 정의한다. 실제 검증 결과는 README 및 제출 점검표에서 관리한다.

## 1. 범위와 기본 동작

각 할 일에는 고유 ID, 제목, 카테고리, 장소, 예상 소요시간, 날짜, 완료 상태와 수행점수가 있다. 날짜를 선택하면 미완료 `해야 할 일`과 완료 `실제로 한 일`, 일일 통계가 보인다. 월 달력에서 과거 날짜의 목록과 회고를 다시 볼 수 있고, 앱을 종료·재실행해도 로컬 기록을 복원한다. 카테고리별로 입력한 장소를 기억하여 자동완성과 장소 관찰 통계를 제공한다.

| 항목 | 정책 |
| --- | --- |
| 제목 | 앞뒤 공백 제거, 빈 제목 금지 |
| 카테고리 | 공부·운동을 기본 선택지로 제공하고 사용자 카테고리 지원 |
| 장소 | 앞뒤 공백 제거, 빈 장소는 `미지정` |
| 예상시간 | 분 단위 정수, 1~1,440분. 기본 30분 |
| 수행점수 | 0~10 정수. 0점도 완료한 일로 인정 |
| 완료 여부 | `score == null`이면 미완료, 점수가 있으면 완료 |
| 날짜 | 기기 로컬 날짜를 `yyyy-MM-dd`로 정규화 |
| 기본 하루 기준량 | 3개, 예상시간 90분. 사용자가 변경 가능 |
| 초기 하루 평점 목표 | 이전 기록이 없으면 7.0점 |
| 데이터 보관 | 로그인·서버 없이 기기의 로컬 저장소에 보관 |
| 회고 | 날짜별 잘한 점·아쉬운 점·개선할 점 직접 입력·저장 |

체크 동작으로 완료할 때 수행점수를 선택한다. 완료한 일의 점수를 수정하거나 완료를 취소할 수 있다. 제목·장소·예상시간·날짜도 수정할 수 있다. 날짜별 기준량과 목표는 계획을 처음 만들 때 저장하며, 기준량은 이후 계획이 늘어날 때만 높아진다.

## 2. 서로 다른 두 점수

**평균 수행점수**는 완료한 일의 품질을 설명한다. **하루 활동 평점**은 점수에 완료한 일의 수와 예상시간까지 반영한다. 두 지표를 같은 이름으로 표시하지 않는다.

| 기호 | 의미 |
| --- | --- |
| C | 선택한 날짜의 완료한 일 개수 |
| sᵢ | 완료한 일 i의 수행점수, 0~10 |
| mᵢ | 완료한 일 i의 예상시간, 분 |
| N | 해당 날짜에 저장한 기준 개수, 1 이상 |
| M | 해당 날짜에 저장한 기준 예상시간, 1분 이상 |

완료한 일이 있으면 평균 수행점수 Q는 `sum(sᵢ) / C`이다. 완료가 없으면 Q는 계산하지 않고 화면에 `—` 또는 `완료한 일 없음`을 표시한다. 0점으로 완료한 일이 있으면 평균은 0점이며, 미완료와 구분한다.

공식으로 사용하는 하루 활동 평점 D는 다음과 같다.

```text
개수 점수 = min(10, 완료한 일의 수행점수 합 / N)
시간 점수 = min(10, 완료한 일의 (수행점수 × 예상시간) 합 / M)
하루 활동 평점 = (개수 점수 + 시간 점수) / 2
```

두 요소에 같은 비중을 주고 각각 10점을 상한으로 둔다. 결과는 항상 0~10이다. 예상시간이 긴 일의 점수는 시간 요소에 더 크게 반영하므로 하루 활동 평점이 단순 품질 평균보다 클 수도 있다. 두 값의 크기 관계를 항상 같다고 설명하지 않는다. 예상시간은 실제 집중시간을 측정한 값이 아니다. 화면 설명에도 `완료한 일의 예상시간`으로 적는다.

추가로 개수 달성률 `min(1, C/N)`과 시간 달성률 `min(1, sum(mᵢ)/M)`을 표시할 수 있다. 이 달성률을 평균 수행점수에 다시 곱하는 방식은 공식으로 사용하지 않는다.

### 이전 초안을 바꾼 이유

평균 수행점수에 개수·시간 달성률을 곱하면, 낮은 점수의 짧은 일을 삭제했을 때 평균이 크게 올라 하루 평점까지 상승할 수 있다. 예를 들어 60분·10점, 60분·10점, 1분·0점의 세 완료 항목에서 기준을 3개·121분으로 고정해도 이전 식은 약 6.67점에서 8.29점으로 상승한다.

확정 공식은 완료 항목의 비음수 점수 기여를 합산한다. 기준 N과 M을 낮추지 않는 동안 완료 삭제나 완료 취소는 합산 기여를 줄이므로 하루 활동 평점을 높일 수 없다. 0점 항목을 없애거나 상한이 적용된 상태에서는 평점이 같을 수 있다. 평균 수행점수는 별도 지표이므로 낮은 점수 항목을 삭제한 뒤 높아질 수 있다.

## 3. 기준량과 날짜별 스냅샷

날짜에 첫 할 일을 추가할 때 하루 기준 개수·예상시간·평점 목표를 `DayPlan`에 저장한다. 개수·예상시간은 그 날짜의 실제 계획량과 비교하여 큰 값을 유지한다.

```text
N = max(저장된 이전 N, 현재 계획한 일 개수)
M = max(저장된 이전 M, 현재 계획한 일의 예상시간 합)
```

처음에는 사용자의 하루 목표 개수·시간으로 N과 M을 시작한다. 삭제·완료 취소·예상시간 감소·다른 날짜로 이동이 일어나도 기존 날짜의 N과 M은 낮추지 않는다. 계획이 늘면 해당 날짜의 기준도 높아질 수 있다. 현재 남아 있는 목록의 합계와 점수 계산에 쓰는 기준량은 화면에서 구분한다.

하루 목표 설정을 바꾸면 새로 계획을 만드는 날짜에 적용한다. 이미 기록이 있는 날짜의 기준량이나 목표를 소급하여 낮추지 않는다. 전체 항목을 삭제해도 기존 `DayPlan`을 지우지 않아, 계획이 있던 날의 0점 기록이 사라지지 않도록 한다. 이를 위해 별도의 완료 원장이나 삭제 항목 복사본을 둘 필요는 없다.

날짜를 옮길 때에는 기존 날짜의 기준을 유지하고 새 날짜의 기준을 새 목록에 맞춰 올린다. 항목의 점수는 지정 날짜의 기록에 반영한다. 완료 버튼을 누른 시각을 별도의 완료 날짜로 사용하지 않는다.

## 4. 평균과 다음 목표

목표 기준 평균은 단순 달력 14일이 아니라 **기록이 있는 최근 최대 14개 날짜**의 하루 활동 평점 평균이다. 날짜는 최신순으로 선정한다. 오늘 이후의 날짜는 평균에서 제외한다.

| 날짜 상태 | 평균 포함 여부 |
| --- | --- |
| 한 번도 계획이 없는 빈 날짜 | 제외 |
| 계획은 있으나 완료가 0개인 날짜 | 0점으로 포함 |
| 모든 항목을 삭제했지만 계획 기록이 남은 날짜 | 0점으로 포함 |
| 0점으로 완료한 일이 있는 날짜 | 0점으로 포함 |
| 미래에 계획한 날짜 | 현재 평균에서 제외 |
| 회고만 있고 계획은 없는 날짜 | 활동 평균에서 제외, 달력에 회고 아이콘 |

새 날짜의 목표를 만들 때에는 그 날짜보다 이전인 기록만 참고하여 자기 자신의 평점이 목표를 바꾸지 않도록 한다.

```text
이전 기록 없음: 목표 7.0점
이전 기록 있음: 목표 min(10, 최근 최대 14개 기록 평점 평균 + 0.5)
```

목표는 날짜별로 저장한다. 과거 기록 수정이나 전역 목표 설정 변경이 기존 날짜의 목표를 다시 계산하지 않는다. 평균이 10점이면 목표도 10점이므로 이 경우에는 `평균보다 높은 목표`라고 표현하지 않고 `최고점 유지 목표`라고 설명한다. 모든 이전 평점이 0점이면 다음 목표는 0.5점이다.

계산에는 반올림 전 값을 사용한다. 표시용 반올림은 계산식이나 기록 평균에 다시 입력하지 않는다. 화면의 숫자 자릿수와 목표 달성 안내는 서로 모순되지 않도록 검증한다.

## 5. 계산 예시

아래 값은 설계 검산 예시이며 실제 앱 실행 로그나 실측 결과가 아니다. `약` 표시는 반올림한 표시값이다.

| 사례 | 기준 N/M | 평균 수행점수 Q | 개수 점수 / 시간 점수 | 하루 활동 평점 D |
| --- | --- | --- | --- | --- |
| 30분·8점의 일 3개 모두 완료 | 3개 / 90분 | 8.00 | 8.00 / 8.00 | 8.00 |
| 같은 계획 중 2개만 완료 | 3개 / 90분 | 8.00 | 약 5.33 / 약 5.33 | 약 5.33 |
| 위에서 미완료 1개 삭제 | 3개 / 90분 유지 | 8.00 | 약 5.33 / 약 5.33 | 약 5.33, 그대로 |
| 위에서 완료 1개를 취소 | 3개 / 90분 유지 | 8.00 | 약 2.67 / 약 2.67 | 약 2.67 |
| 90분·8점의 일 1개 완료 | 3개 / 90분 | 8.00 | 약 2.67 / 8.00 | 약 5.33 |
| 20분·8점의 일 3개 완료 | 3개 / 90분 | 8.00 | 8.00 / 약 5.33 | 약 6.67 |
| 60분·10점 2개와 1분·0점 1개 완료 | 3개 / 121분 | 약 6.67 | 약 6.67 / 약 9.92 | 약 8.29 |
| 위에서 1분·0점 완료 항목 삭제 | 3개 / 121분 유지 | 10.00 | 약 6.67 / 약 9.92 | 약 8.29, 상승 없음 |
| 계획은 있으나 완료 없음 | 저장 기준 유지 | 계산하지 않음 | 0 / 0 | 0 |

긴 일 한 개를 완료하면 시간 요소에는 반영되지만 개수 요소가 낮게 남는다. 같은 점수의 완료량이 감소하면 평점이 내려간다. 점수 0인 일은 완료 개수에는 포함되어도 점수 기여는 0이다.

## 6. 저장·실패·경계 사례

| 상황 | 기대 동작 |
| --- | --- |
| 첫 실행, 저장 데이터 없음 | 빈 목록과 기본 하루 목표로 시작 |
| 앱 종료·재실행 | 저장된 항목·날짜·점수·기준량·목표·다음 ID 복원 |
| 저장이 아직 진행 중 | 중복 입력을 제어하고 작업 완료를 기다림 |
| 저장 실패 | 실패 안내, 성공한 것처럼 화면을 갱신하지 않음 |
| 여러 변경 요청이 연속으로 발생 | 요청을 순서대로 저장하여 뒤 요청이 앞 요청을 덮어쓰지 않음 |
| 잘못된 JSON·지원하지 않는 버전 | 읽기 오류 안내. 저장 기록을 자동 초기화하지 않음 |
| 같은 제목 여러 개 | 고유 ID로 수정·삭제하므로 원하는 항목만 변경 |
| 저장 ID 중복·다음 ID 역행 | 잘못된 저장 자료로 거부 |
| 점수 0과 null | 0은 완료, null은 미완료 |
| 잘못된 날짜·예상시간·목표·점수 | 모델 또는 입력 단계에서 검증하고 거부 |
| 월·연도 변경, 윤년 | 유효한 로컬 날짜만 표시·저장 |
| 낮은 점수의 완료 항목 삭제 | 품질 평균은 변할 수 있지만 활동 평점은 상승하지 않음 |
| 미래 날짜에 할 일을 예약 | 달력과 목록에는 보이되 현재 평균에 포함하지 않음 |

현재 설계는 `SharedPreferencesAsync`에 버전 2 JSON을 저장한다. Riverpod `AsyncNotifierProvider`가 읽기·저장과 비동기 상태를 관리하고, 저장이 성공한 다음 새 상태를 공개한다. 항목과 날짜별 계획은 불변 컬렉션으로 새 값을 만들어 갱신한다.

로컬 저장은 사용자 기기에서 앱 재시작 후 기록을 보관하는 용도다. 기기 변경·프로필 삭제·앱 데이터 초기화·클라우드 동기화까지 보장하는 백업 기능은 범위에 포함하지 않는다.

## 7. 장단점과 한계

장점은 0~10 범위에서 완료 품질과 활동량을 함께 읽을 수 있고, 삭제·완료 취소·목표 감소로 기존 날짜의 분모를 줄여 평점을 올리는 동작을 막는다는 점이다. 날짜별 목표를 저장하여 기록을 수정하더라도 과거 목표는 안정적으로 남는다.

기준량이 계획의 최고값으로 남으므로 잘못 입력한 긴 예상시간이나 과한 계획도 당일 기준에 남을 수 있다. 이는 점수 상승을 위한 계획 삭제를 막는 정책의 비용이다. 화면에 `오늘 기준은 계획을 늘릴 때만 높아지며 삭제해도 줄지 않습니다`라고 설명한다. 초기화·기록 삭제 기능을 추가한다면 계산 기준을 다시 낮출 수 있는 효과를 별도로 설명해야 한다.

수행점수는 사용자가 평가한 값이고 시간은 예상치다. 작업을 잘게 나누거나 예상시간·수행점수를 높이면 결과가 달라질 수 있다. 수정 기능을 지원하는 현재 범위에서 모든 조작 가능성을 제거했다고 주장하지 않는다. 완료 삭제·취소에 대한 상승 방지와 수행점수·예상시간 수정의 효과를 구분한다.

고정 기준에서 점수와 예상시간이 음수가 아니며 완료 기여를 제거하는 경우에만 비상승 성질이 보장된다. 편집으로 점수·시간을 늘리거나 다른 날짜에 기여를 옮기는 동작에 같은 보장을 적용하지 않는다. 비교는 개인 기록의 변화에 사용하며 객관적 업무 성과 측정값으로 설명하지 않는다.

## 8. 화면에 사용할 짧은 설명

- 평균 수행점수: `완료한 일의 점수 평균입니다. 완료한 일이 없으면 평균을 계산하지 않습니다.`
- 하루 활동 평점: `점수 합과 예상시간을 반영한 점수 합을 하루 기준량으로 나누어 평균합니다.`
- 기준량: `처음 설정한 하루 목표와 지금까지 계획한 최대량 중 큰 값을 사용합니다. 삭제해도 기준은 줄지 않습니다.`
- 목표: `기록이 있는 이전 최대 14일의 활동 평점 평균보다 0.5점 높게 정합니다. 최대 10점입니다.`
- 기록 평균: `빈 날짜와 미래 날짜는 빼고, 계획했지만 완료가 없는 날은 0점으로 포함합니다.`
- 설정: `바꾼 개수·시간 목표는 새로 계획하는 날짜부터 적용됩니다.`

## 9. 완료 조건과 증빙 대응

실제 통과 여부는 `docs/submission_checklist.md`에서 갱신한다. 아래는 요구 조건이며 아직 수행한 검증 결과를 뜻하지 않는다.

| 검증 종류 | 확인할 조건 |
| --- | --- |
| 모델·계산 테스트 | 0점 완료, 상한 10, 완료 0개, 두 점수 구분, 위 계산 예시 |
| 삭제·취소 회귀 테스트 | 낮은 점수·짧은 항목 삭제 및 취소 후 활동 평점 비상승 |
| 기준 스냅샷 테스트 | 계획 증가, 삭제·시간 감소·목표 변경 후 기존 기준 유지 |
| 날짜·평균 테스트 | 빈 날 제외, 계획만 있는 날 0 포함, 미래 제외, 최근 기록 최대 14개 |
| 목표 테스트 | 초기 7점, 평균+0.5, 상한 10, 저장된 날짜 목표 불변 |
| 저장 테스트 | JSON 왕복, 고유 ID·날짜 검증, 잘못된 자료, 저장 실패·연속 요청 |
| 위젯 테스트 | 추가·수정·삭제, 장소·시간, 점수 입력·완료 취소, 달력·목표 설정 |
| 네이티브 검증 | 실제 입력·변경 후 프로세스 종료·재실행에서 기록 복원 |
| 캡처 | 기본 기능 5장·DevTools 4장·점수/달력/설정 5장과 카테고리·장소 관찰·회고의 새 증빙 |

촬영용 과거 샘플은 메모리 저장소로 주입하고 일반 앱의 실제 사용자 저장소와 분리한다. 촬영 화면에 샘플이 있다는 사실과 별도 로컬 저장 검증의 입력·재시작 결과를 문서에 구분하여 적는다.

## 10. 카테고리와 장소 목록

`Todo.category`는 공부·운동 또는 사용자 카테고리를 구분한다. 같은 장소 이름이라도 카테고리가 다르면 다른 관찰 집단으로 처리한다. 장소 카탈로그는 `category → 장소 목록` 자료구조로 로컬에 보관한다.

사용자가 할 일을 추가·수정하면서 새 장소를 입력하면 저장 성공 시 해당 카테고리의 장소 목록에도 등록한다. 같은 카테고리에 같은 이름을 반복 입력해 중복 후보가 생기지 않게 앞뒤·연속 공백을 정규화한다. 빈 카테고리는 `기타`, 빈 장소는 `미지정`으로 처리한다. 카테고리를 바꾸면 그 카테고리의 장소만 자동완성 후보로 제공한다. 항목 삭제로 장소 후보 자체를 자동 삭제하지 않아 이전에 입력한 장소를 다시 사용할 수 있게 한다. `미지정`은 자동완성 후보에 넣지 않으며, 관찰 표에 표시되더라도 실제 이름을 입력한 장소와 구분한다.

자동완성은 장소 이름을 빠르게 다시 입력하도록 돕는다. 통계가 좋은 장소를 미래의 성공 장소로 예측하는 기능으로 설명하지 않는다. 카테고리·장소·자동완성 목록도 종료·재실행 후 복원하는 검증에 포함한다.

## 11. 장소별 관찰 통계

각 카테고리·장소의 관찰은 **현재 보관된 할 일 중 지정 날짜가 오늘 이하인 항목**을 대상으로 계산한다. 미래 날짜는 제외한다. 일일 점수의 기준 스냅샷과 다르게 실제 남아 있는 항목 수를 표본 수로 사용한다.

```text
계획 표본 n = 해당 카테고리·장소의 과거/오늘 항목 수
관찰 성공 수 = 그중 완료했고 수행점수가 8 이상인 항목 수
관찰 성공률 = 관찰 성공 수 / n × 100%
완료 평균점수 = 완료 항목의 점수 합 / 완료 항목 수
완료 예상분 = 완료 항목에 입력한 예상분의 합
```

미완료 항목도 n에 포함된다. 완료했지만 7점 이하인 항목은 완료 평균과 완료 예상분에는 포함되고 관찰 성공 수에는 포함되지 않는다. 완료 항목이 없으면 평균을 계산하지 않는다. n이 0이면 `자료 없음`으로 표시하며 0% 성공률로 해석하지 않는다.

예를 들어 같은 카테고리·장소에서 9점 완료, 7점 완료, 미완료가 각 1개라면 `관찰 성공률 33.3% (1/3)`이다. 완료 평균은 8점이며 미완료를 평균점수의 0점으로 넣지 않는다. 이는 설명용 산술 예시이며 실제 검증 결과가 아니다.

화면에는 성공률과 함께 n 또는 성공 수/계획 수를 표시한다. 표본 1개의 100%를 가장 좋은 장소의 확실한 근거로 설명하지 않는다. 통계는 자기 기록에 대한 관찰 비율이며 예측 확률·인과 효과가 아니다. 항목 삭제나 장소·카테고리·날짜 수정으로 표본과 비율은 달라질 수 있다. 삭제 전의 항목까지 보존한 감사 원장이라고 설명하지 않는다.

## 12. 완료·미완료 목록과 날짜별 회고

선택 날짜의 목록은 `해야 할 일`과 `실제로 한 일`로 나눈다. `score == null`은 해야 할 일, 점수가 0~10이면 실제로 한 일에 둔다. 완료 점수 저장 시 두 번째 목록으로 이동하고 완료 취소 시 첫 번째 목록으로 돌아간다. 두 목록이 같은 항목을 중복 표시하거나 날짜 밖의 항목을 섞지 않도록 한다.

`DayReflection`은 날짜별로 `good`(잘한 점), `needsWork`(아쉬운 점), `improve`(개선할 점)를 보관한다. 사용자가 직접 쓰고 명시적으로 저장한다. 날짜를 바꾸어 해당 날짜의 회고를 읽고 수정하며 종료·재실행 후 같은 내용을 복원한다. 저장 실패 시 입력을 잃지 않게 하고 저장되지 않은 내용을 저장 완료로 표시하지 않는다.

**회고 저장은 DayPlan을 만들지 않는다.** 회고만 작성한 날짜는 달력에 회고 아이콘으로 표시하고, 계획 기준이나 하루 0점 기록·14기록일 활동 평균에 편입하지 않는다. 이미 계획이 있던 날짜의 회고를 수정해도 계획·활동 점수 기준을 바꾸지 않는다. 세 회고 필드를 모두 비워 저장하면 해당 회고만 제거하고 계획 기록은 유지한다.

기존 version 2 자료에 category·placeCatalog·reflections가 없으면 category는 기타, 회고는 빈 값으로 읽고 기존 항목의 장소로 카탈로그를 보완한다. 기존 항목·점수·계획을 보존하며 최종 저장 호환성 검사에 이 자료를 포함한다.
